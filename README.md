# 📊 Applicant Data Cleaning & Exploratory Data Analysis

## 📌 Project Overview

This project was completed as part of the **NextGen Learners Remote Data Science Internship**. It focuses on preparing an applicant dataset for analysis and exploring it through data visualisation using Python.

The project covers two stages: **Week 1 — Data Cleaning** and **Week 2 — Exploratory Data Analysis (EDA)**. Together, these stages demonstrate how data can be inspected, cleaned, validated, and analysed to identify meaningful patterns.

## 🎯 Project Objectives

- Identify and handle missing values, duplicate records, and inconsistent data.
- Improve data quality through cleaning and validation.
- Explore application patterns across domains, universities, dates, and statuses.
- Create visualisations to communicate findings.
- Develop practical data science and analytical skills.

## 🛠️ Tools and Technologies

- **Python** — programming and analysis.
- **Pandas** — data cleaning and manipulation.
- **Matplotlib & Seaborn** — data visualisation.
- **Google Colab** — writing and running the notebook.
- **GitHub** — project storage and version control.

## 📂 Dataset

The applicant dataset contains the following fields:

- Applicant Name
- Email
- Phone
- Domain Applied
- University
- Application Date
- Status

Both the original dataset (`applicants.csv`) and cleaned dataset (`applicants_cleaned.csv`) are used to support data-quality assessment and subsequent analysis.

## 🧹 Week 1: Data Cleaning

The first stage focused on preparing the dataset for analysis.

Tasks included:

- Inspecting the dataset's structure and data types.
- Identifying and handling missing values.
- Detecting and removing duplicate records where appropriate.
- Investigating and correcting inconsistent data.
- Validating the cleaned dataset.
- Exporting the cleaned data for further analysis.

## 📈 Week 2: Exploratory Data Analysis

The second stage explored the cleaned dataset using five visualisations:

1. **Applications per Domain** — compares application volumes across domains.
2. **Monthly Application Trends** — explores how application volumes change over time.
3. **Application Status Breakdown** — compares selected, rejected, and under-review applications.
4. **Application Status by Domain** — examines how outcomes differ across domains.
5. **Applications by Day of the Week** — explores differences in submission activity across the week.

### Key Findings

- Web Development and Software Engineering each recorded 20 applications.
- April, June, and July each recorded 11 applications, while September recorded the fewest, with 2.
- Under Review was the most common status, with 33 applications, followed by Rejected (23) and Selected (21).
- Wits recorded 20 applications, followed by UKZN with 17.
- Friday recorded the most applications by day of the week (14), while Tuesday and Saturday each recorded 7.

These findings reflect the recorded category values in the dataset used for the analysis.
